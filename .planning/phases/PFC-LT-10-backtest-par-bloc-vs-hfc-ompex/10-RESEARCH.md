### Pattern 1: Block mask class-based (tz Europe/Zurich)
**What:** Encapsuler les 5 blocs comme classes uniformes avec une méthode `apply(idx_tz) -> np.ndarray[bool]`.
**When to use:** À chaque cellule (bloc × horizon × vintage × config), pour filtrer pred/realised avant agrégation.
**Example (canonique, à implémenter dans `block_masks.py`):**
```python
# Source: design inspired by pfc_shaping/data/calendar_ch.py enrich_15min_index pattern
from __future__ import annotations
import numpy as np
import pandas as pd
import holidays

class BlockMask:
    """Base class: takes tz-aware DatetimeIndex, returns boolean mask."""
    name: str = "base"

    def apply(self, idx_utc: pd.DatetimeIndex) -> np.ndarray:
        """Return bool array aligned on idx_utc (tz=UTC), True = in bloc.

        Always converts internally to Europe/Zurich for human-readable bloc
        definition (heures locales suisses), then maps back to UTC mask.
        """
        if idx_utc.tz is None:
            raise ValueError("Index must be tz-aware (UTC expected).")
        idx_local = idx_utc.tz_convert("Europe/Zurich")
        return self._mask_local(idx_local)

    def _mask_local(self, idx_local: pd.DatetimeIndex) -> np.ndarray:
        raise NotImplementedError


class BlockOvernightWeekday(BlockMask):
    """18h-09h, Lun-Ven, all months. Crosses midnight."""
    name = "block_overnight_weekday"
    def _mask_local(self, idx_local):
        is_weekday = idx_local.weekday < 5
        hour_mask = (idx_local.hour >= 18) | (idx_local.hour < 9)
        return (is_weekday & hour_mask).to_numpy()


class BlockMiddayWeekday(BlockMask):
    """10h-15h, Lun-Ven, all months."""
    name = "block_midday_weekday"
    def _mask_local(self, idx_local):
        is_weekday = idx_local.weekday < 5
        hour_mask = (idx_local.hour >= 10) & (idx_local.hour < 15)
        return (is_weekday & hour_mask).to_numpy()


class BlockWeekendMidday(BlockMask):
    """11h-15h, Sam-Dim, all months."""
    name = "block_weekend_midday"
    def _mask_local(self, idx_local):
        is_weekend = idx_local.weekday >= 5
        hour_mask = (idx_local.hour >= 11) & (idx_local.hour < 15)
        return (is_weekend & hour_mask).to_numpy()


class BlockSummerSolarBowl(BlockMask):
    """11h-14h, all DOW, mai-août. Test 5bis-B duck curve."""
    name = "block_summer_solar_bowl"
    def _mask_local(self, idx_local):
        hour_mask = (idx_local.hour >= 11) & (idx_local.hour < 14)
        month_mask = (idx_local.month >= 5) & (idx_local.month <= 8)
        return (hour_mask & month_mask).to_numpy()


class BlockWinterEveningPeak(BlockMask):
    """17h-21h, Lun-Ven, nov-fév."""
    name = "block_winter_evening_peak"
    def _mask_local(self, idx_local):
        is_weekday = idx_local.weekday < 5
        hour_mask = (idx_local.hour >= 17) & (idx_local.hour < 21)
        month_mask = (idx_local.month >= 11) | (idx_local.month <= 2)
        return (is_weekday & hour_mask & month_mask).to_numpy()


ALL_BLOCKS: list[BlockMask] = [
    BlockOvernightWeekday(),
    BlockMiddayWeekday(),
    BlockWeekendMidday(),
    BlockSummerSolarBowl(),
    BlockWinterEveningPeak(),
]
```

**Critical DST note:** `tz_convert("Europe/Zurich")` on a UTC index is **always safe** (no fold ambiguity, no nonexistent hours) because the index is canonical UTC. The mask is computed on local hours which is what trader convention requires — DST transitions happen at 02:00 local Europe/Zurich (last Sun March → 03:00 ; last Sun October → 02:00), neither of which fall in any of the 5 bloc hour ranges. **Aucune mitigation DST spéciale requise.** [VERIFIED: pandas docs `tz_convert` is unambiguous from UTC source]

### Pattern 2: Mincer-Zarnowitz joint test via statsmodels `OLS.f_test`
**What:** Régression `realised = α + β·predicted + ε` + test joint `α=0 & β=1`. Si p > 0.05 → unbiased forecast (cohérent avec MZ classique).
**When to use:** Per (bloc × horizon × config) cellule, après agrégation hourly mean sur les rows-in-bloc.
**Example:**
```python
# Source: statsmodels 0.14 docs OLSResults.f_test [CITED: statsmodels.org/stable/generated/statsmodels.regression.linear_model.OLSResults.f_test.html]
import statsmodels.api as sm
import pandas as pd

def mz_test(realised: pd.Series, predicted: pd.Series) -> dict:
    """Mincer-Zarnowitz joint unbiasedness test.

    Returns dict with alpha, beta, p_value (joint H0: alpha=0, beta=1).
    """
    aligned = pd.concat([realised, predicted], axis=1, join="inner").dropna()
    aligned.columns = ["realised", "predicted"]
    X = sm.add_constant(aligned["predicted"])
    y = aligned["realised"]
    fit = sm.OLS(y, X).fit()
    # Joint test: intercept (const) = 0 AND slope (predicted) = 1
    f_result = fit.f_test("const = 0, predicted = 1")
    return {
        "alpha": float(fit.params["const"]),
        "beta": float(fit.params["predicted"]),
        "p_value_joint_unbiased": float(f_result.pvalue),
        "n_obs": int(len(aligned)),
        "r_squared": float(fit.rsquared),
    }
```

**API note (statsmodels 0.14.x):** `.f_test()` exists and is preserved as a convenience wrapper around `.wald_test(use_f=True)`. Both are valid — `.f_test()` is more explicit for forecast eval [CITED: statsmodels.org/stable/generated/statsmodels.regression.linear_model.OLSResults.f_test.html]. Constraint strings accept variable names from the model (in our case `const` for the intercept and `predicted` for the slope coefficient).

### Pattern 3: Christoffersen unconditional coverage via binomial LR
**What:** Test si la fréquence empirique d'observations tombant dans l'IC nominal (80% ou 95%) est statistiquement égale à la cible.
**When to use:** Per (bloc × horizon × config) cellule, comparant `(observed_freq, nominal_p)`.
**Example:**
```python
# Source: Christoffersen 1998 LR_uc formula [CITED: value-at-risk.net/backtesting-coverage-tests/]
import numpy as np
from scipy.stats import chi2

def lr_unconditional_coverage(x: int, n: int, p: float) -> dict:
    """Christoffersen (1998) LR_uc test for unconditional coverage.

    H0: observed_freq == nominal p.
    LR_uc = -2 * log( (p^x * (1-p)^(n-x)) / (pi_hat^x * (1-pi_hat)^(n-x)) )
    Distribution: chi-squared with 1 df.

    Args:
        x: count of observations OUTSIDE the IC (violations)
        n: total observations
        p: nominal violation probability (e.g. 0.20 for IC80, 0.05 for IC95)

    Returns:
        dict with lr_stat, p_value, observed_freq, nominal_p, n, x
    """
    if n == 0 or x == 0 or x == n:
        # Degenerate case — return p_value=NaN, caller must handle
        return {
            "lr_stat": float("nan"),
            "p_value": float("nan"),
            "observed_freq": float("nan") if n == 0 else x / n,
            "nominal_p": p,
            "n": n,
            "x": x,
            "degenerate": True,
        }
    pi_hat = x / n
    # Use log-formulation for numerical stability
    log_lik_null = x * np.log(p) + (n - x) * np.log(1 - p)
    log_lik_alt = x * np.log(pi_hat) + (n - x) * np.log(1 - pi_hat)
    lr_stat = -2.0 * (log_lik_null - log_lik_alt)
    p_value = float(chi2.sf(lr_stat, df=1))
    return {
        "lr_stat": float(lr_stat),
        "p_value": p_value,
        "observed_freq": pi_hat,
        "nominal_p": p,
        "n": n,
        "x": x,
        "degenerate": False,
    }
```

**Interpretation in scorecard cell:** `IC80 — obs 78% (148/190) — p=0.412 PASS` (PASS = p > 0.05, fail to reject H0 = unconditional coverage is correct).

### Pattern 4: Diebold-Mariano with Newey-West HAC + HLN small-sample correction
**What:** Test si la loss differential moyenne entre forecast A et forecast B est significativement nulle (cohérent vs equal accuracy).
**When to use:** Per (bloc × baseline × horizon × config), 3 baselines maison vs PFC.
**Example (à implémenter dans `dm_test.py` — maison ~30 lignes, ZÉRO dep externe):**
```python
# Source: Diebold-Mariano (1995) + Harvey-Leybourne-Newbold (1997) small-sample correction
# References: pkg.robjhyndman.com/forecast/reference/dm.test.html (R reference impl)
#             real-statistics.com/time-series-analysis/forecasting-accuracy/diebold-mariano-test/
from __future__ import annotations
import numpy as np
from scipy.stats import t as student_t
from statsmodels.tsa.stattools import acovf

def diebold_mariano(
    errors_a: np.ndarray,
    errors_b: np.ndarray,
    h: int = 1,
    loss: str = "mae",
    hln_correction: bool = True,
) -> dict:
    """DM test: H0 = equal accuracy between forecast A and forecast B.

    Args:
        errors_a: forecast errors of A (realised - pred_a) or (pred_a - realised),
                  consistent sign across both inputs.
        errors_b: forecast errors of B, same convention.
        h: forecast horizon in periods. HAC lag = h - 1 (DM 1995 recommendation).
        loss: 'mae' (loss = |e|) or 'mse' (loss = e^2).
        hln_correction: apply Harvey-Leybourne-Newbold (1997) small-sample correction.

    Returns:
        dict with dm_stat, p_value (two-sided), n, mean_d, var_d, n_lags_hac.

    Notes:
        * Loss differential: d_t = L(e_a_t) - L(e_b_t). Mean negative => A is better.
        * HAC variance: gamma_0 + 2 * sum_{k=1..h-1} (1 - k/h) * gamma_k  (Bartlett-like
          weighting via simple truncation, DM 1995 §3.1).
        * If HAC variance is negative (rare edge case, can happen for h>=2 if
          sample is short and acovf produces near-zero positive plus larger negative
          weighted gammas), the formula degenerates. Mitigation: fall back to
          sample variance (lag=0) and emit a logger.warning. Documented edge case
          per `arch` package +DM 1995 §3.2 footnote.
    """
    if len(errors_a) != len(errors_b):
        raise ValueError(f"Length mismatch: a={len(errors_a)}, b={len(errors_b)}")
    n = len(errors_a)
    if n < max(h + 1, 8):
        # Too few obs for a meaningful HAC variance with this horizon
        return {"dm_stat": float("nan"), "p_value": float("nan"),
                "n": n, "mean_d": float("nan"), "var_d": float("nan"),
                "n_lags_hac": h - 1, "degenerate": True}

    # Loss differential
    if loss == "mae":
        d = np.abs(errors_a) - np.abs(errors_b)
    elif loss == "mse":
        d = errors_a ** 2 - errors_b ** 2
    else:
        raise ValueError(f"loss must be 'mae' or 'mse', got {loss!r}")

    d_mean = float(np.mean(d))
    n_lags = max(h - 1, 0)

    # Newey-West-like HAC long-run variance via acovf (sample autocovariances)
    # gamma[0] = sample variance; gamma[k] = sample lag-k autocovariance
    gammas = acovf(d, nlag=n_lags, fft=True, demean=True)  # length n_lags+1
    # DM 1995 truncated estimator: gamma_0 + 2 * sum_{k=1..h-1} gamma_k
    # (uniform weights; the alternative Bartlett kernel uses (1 - k/h) weights and
    # is positive-semidefinite by construction.)
    if n_lags == 0:
        var_d = float(gammas[0])
    else:
        # Use Bartlett weights for positivity (R forecast::dm.test default for h>1)
        weights = 1.0 - np.arange(1, n_lags + 1) / float(n_lags + 1)
        var_d = float(gammas[0] + 2.0 * np.sum(weights * gammas[1:]))

    # Edge case: variance negative or zero (rare but documented in DM 1995 §3.2)
    if var_d <= 0:
        # Fallback: use sample variance (lag=0 only)
        # Note: emit a warning at caller level — keep this fn pure
        var_d = float(gammas[0])
        if var_d <= 0:
            return {"dm_stat": float("nan"), "p_value": float("nan"),
                    "n": n, "mean_d": d_mean, "var_d": var_d,
                    "n_lags_hac": n_lags, "degenerate": True}

    dm_stat = d_mean / np.sqrt(var_d / n)

    # HLN small-sample correction (Harvey, Leybourne, Newbold 1997)
    # adj = sqrt( (n + 1 - 2*h + h*(h-1)/n) / n )
    if hln_correction:
        adj = np.sqrt(max((n + 1 - 2 * h + h * (h - 1) / n) / n, 1e-12))
        dm_stat = dm_stat * adj
        # Use Student-t with n-1 df instead of N(0,1) for p-value
        p_value = float(2 * student_t.sf(abs(dm_stat), df=n - 1))
    else:
        from scipy.stats import norm
        p_value = float(2 * norm.sf(abs(dm_stat)))

    return {
        "dm_stat": float(dm_stat),
        "p_value": p_value,
        "n": n,
        "mean_d": d_mean,
        "var_d": var_d,
        "n_lags_hac": n_lags,
        "degenerate": False,
    }
```

**HAC weight choice rationale:** Bartlett-like weights `(1 - k/(h+1))` ensure positive semi-definite variance estimator by construction [CITED: pkg.robjhyndman.com `varestimator="bartlett"`]. The uniform-weight estimator from DM 1995 §3.1 can produce negative variance in small samples. We use Bartlett as the canonical safe default.

**Edge cases documented:**
1. `var_d ≤ 0` after Bartlett weighting (extremely rare) → fallback to sample variance (lag=0)
2. `var_d ≤ 0` even at lag=0 → return NaN p-value, mark cell `degenerate=True` in scorecard
3. `n < max(h+1, 8)` → too few obs for HAC, return NaN. Our setting: n=24 vintages × len-of-bloc per vintage, so even for h=24 (Y+2), we always have n>>h+1.

**HLN correction rationale:** R forecast pkg uses HLN by default. With our n=24 vintages and h up to 24 months, HLN is recommended (h > 1 and small n) [CITED: real-statistics.com/Diebold-Mariano + econstor.eu/Döhrn 2019].

**What:** Iterer sur (24 vintages × 4 configs), pour chaque (vintage, config) appeler `assembler.build(reference_date=vintage)`, puis dispatch aux 4 pilliers.
**When to use:** Le coeur de `scorecard.py`. Sépare le grid-loop de la math.

from dataclasses import dataclass
import pandas as pd
from pfc_shaping.lt.model.assembler import PFCAssembler
from pfc_shaping.lt.model.shape_hourly import ShapeHourly
from pfc_shaping.lt.model.shape_intraday import ShapeIntraday
from pfc_shaping.lt.model.uncertainty import Uncertainty

@dataclass(frozen=True)
class AblationConfig:
    name: str                   # "bowl_off_floors_on", etc.
    use_seasonal_hourly: bool   # bowl flag
    enforce_positivity: bool    # MSFC floor
    enforce_m_factor_floor: bool
    enforce_floor: bool          # WV floor
    allow_negative_peak: bool

ABLATION_GRID: list[AblationConfig] = [
    AblationConfig("bowl_off_floors_on",  False, True,  True,  True,  False),  # legacy
    AblationConfig("bowl_on_floors_on",   True,  True,  True,  True,  False),  # 5bisB no Phase5
    AblationConfig("bowl_off_floors_off", False, False, False, False, True),   # Phase5 no 5bisB
    AblationConfig("bowl_on_floors_off",  True,  False, False, False, True),   # PRODUCTION TARGET
]

def list_vintages_2024_2025() -> list[pd.Timestamp]:
    """24 vintages: last business day of each month 2024-01..2025-12, tz UTC."""
    out = []
    for year in (2024, 2025):
        for month in range(1, 13):
            # last business day of (year, month) in Europe/Zurich → UTC
            from pandas.tseries.offsets import BMonthEnd
            last_bd_local = pd.Timestamp(f"{year}-{month:02d}-01", tz="Europe/Zurich") + BMonthEnd(0)
            # Pin to 18:00 local Europe/Zurich (post-market close convention)
            last_bd_local = last_bd_local.replace(hour=18, minute=0)
            out.append(last_bd_local.tz_convert("UTC"))
    return out

def build_one(
    config: AblationConfig,
    vintage: pd.Timestamp,
    epex_hist: pd.DataFrame,
    forwards_asof: dict,
    with_uncertainty: bool = False,
) -> pd.DataFrame:
    """Build a single PFC for (config, vintage). 1 of 96 grid points."""
    # Fit shape on historical data UP TO vintage (no leakage)
    train_mask = epex_hist.index < vintage
    cal_train = enrich_15min_index(epex_hist.index[train_mask])
    sh = ShapeHourly(use_seasonal_hourly=config.use_seasonal_hourly).fit(
        epex_hist.loc[train_mask], cal_train,
    )
    si = ShapeIntraday().fit(epex_hist.loc[train_mask], None, cal_train)
    unc = (
        Uncertainty(n_boot=500, seed=42).fit(epex_hist.loc[train_mask], cal_train)
        if with_uncertainty else None
    )
    assembler = PFCAssembler(
        sh, si, unc,
        enforce_positivity=config.enforce_positivity,
        enforce_m_factor_floor=config.enforce_m_factor_floor,
        enforce_floor=config.enforce_floor,
        allow_negative_peak=config.allow_negative_peak,
    )
    pfc = assembler.build(
        base_prices=forwards_asof,
        start_date=vintage.strftime("%Y-%m-%d"),
        horizon_days=3 * 365,  # Y+3 for full coverage of M+1..Y+2 horizons
        reference_date=vintage,
    )
    return pfc
```

### Anti-Patterns to Avoid
- **Double-tz conversion:** ne JAMAIS faire `tz_localize` sur un index UTC (déjà tz-aware). Toujours `tz_convert("Europe/Zurich")`. `enrich_15min_index` raise déjà sur tz-naive (calendar_ch.py:127).
- **Mean over heterogeneous horizons:** ne jamais agréger MAE across horizons (M+1 et Y+2 ne sont pas comparables). Toujours per-horizon ET aggregate-of-aggregate dans le scorecard.
- **MZ regression sans align:** TOUJOURS `pd.concat(..., axis=1, join="inner").dropna()` AVANT `OLS`. statsmodels lèvera une erreur muette si indices ne s'alignent pas (sépare via reset_index).
- **DM avec h=0:** ne jamais. Notre cas plancher est h=1 (M+1), donc lag=0, sample variance. La fn DM ci-dessus le gère.
- **PFC build without `reference_date`:** vintage 2024-06-28 sans `reference_date=` → assembler utilise `pd.Timestamp.now()` ≈ 2026-05-20 → `months_ahead < 0` → curve inflée (commentaire backtest.py:198-201 documente ce piège, déjà corrigé Bloc C2). Toujours passer `reference_date=vintage` dans le 96-grid.
- **Sub-component re-use across configs:** Phase 5 WR-03 review fix (assembler.py:284-309) — si on construit plusieurs PFCAssembler sur le MÊME cascader/calibrator/wv, le 2ème assembler mute les attributs `enforce_*` du sub-component partagé. Mitigation : construire de NOUVELLES instances `WaterValueCorrection`/`ArbitrageFreeCalibrator`/`ContractCascader` à chaque (config, vintage). Le harness `build_one()` ci-dessus fait fit-from-scratch chaque fois → aucune contamination.

## Common Pitfalls

### Pitfall 1: Hildmann holiday-weekend ratio fails on Config 4 (production target) — RISK FLAG ⚠️
**What goes wrong:** SC#1 gate requires `mean(PFC | weekend ∪ jours_fériés) / mean(PFC | weekday hors fériés) ∈ [0.65, 0.95]` on Config 4 = bowl ON + floors OFF (target post-5bis-B+5). With floors OFF, weekend solar bowl can dip to -20 €/MWh while weekday evening peak rises to +120 €/MWh. Mean ratio becomes (-5 / 80) ≈ -0.06, way outside [0.65, 0.95].
**Why it happens:** Phase 5 removed 4 floors precisely to let prices go negative when forwards are negative. Phase 5bis-B bowl deepens the midday dip in summer. Both effects compound on Config 4. The Hildmann 2013 threshold [0.65, 0.95] was calibrated on positive-only CH historical data (2010-2013 era pre-PV-boom), not on a 2024-2025 negative-prone market.
**How to avoid:** Three options, in order of preference:
1. **Recommend at Plan 10-02:** Compute the ratio on **2019-2023 EPEX historical first** (the "convention CH typical" baseline). If 2019-2023 itself falls outside [0.65, 0.95], the threshold is obsolete and must be **re-calibrated empirically** (e.g. 10th-90th percentile of monthly EPEX-realised ratios over 2019-2023 → new [low, high] range). Document the re-calibration in 10-VERIFICATION.md.
2. **Alternative:** Compute the ratio excluding the `block_summer_solar_bowl` hours (11h-14h May-Aug) — these are the negative-price hours that distort the average. This is the SOTA-grade "exclude PV-driven hours from the holiday/weekend test" fix used by KYOS post-2022.
3. **Last resort (NOT recommended):** Relax the threshold to [0.50, 1.05]. Loses SOTA-grade equivalence with the literature. AVOID.
**Warning signs:** Plan 10-02 task: BEFORE running on Config 4, run on 2019-2023 EPEX hist directly and report the empirical ratio. If < 0.65 or > 0.95 → trigger option 1 or 2 above before evaluating PFC.
**Provenance:** [ASSUMED — ratio observed risk from compounding Phase 5+5bis-B physics; needs empirical verification in Plan 10-02 — flag for user confirmation]

### Pitfall 2: Walk-forward leakage on shape fit
**What goes wrong:** If `ShapeHourly().fit(epex_hist, cal_train)` is called with `epex_hist` that includes data POSTERIOR to the vintage date, the shape "knows" the future and KPIs are artificially optimistic.
**Why it happens:** Reusing a pre-fit `sh` instance across vintages, or filtering `train_mask` incorrectly.
**How to avoid:** ALWAYS re-fit `ShapeHourly`, `ShapeIntraday`, `Uncertainty` from scratch on `epex_hist.loc[epex_hist.index < vintage]` (strict `<`, not `≤`) at each grid point. The `build_one()` skeleton (Pattern 5) does this correctly.
**Warning signs:** MAE values suspiciously close to zero, especially for Y+2 horizon. If MAE on Y+2 is similar to MAE on M+1, leakage is highly likely.

### Pitfall 3: DST transition rows in 15-min cache
**What goes wrong:** Last Sunday of October (CH switches CEST → CET at 03:00 → 02:00) creates duplicated local-time rows. Resampling `15-min → 1h` with `.resample("1h").mean()` on a UTC index handles this correctly (UTC has no DST), but converting to local for bloc masks then resampling can produce phantom 25-hour days.
**Why it happens:** Mixing tz layers. UTC-canonical + last-mile local conversion is safe; local-canonical + intermediate ops is unsafe.
**How to avoid:** Keep the UTC index as the canonical key throughout. Only convert to `Europe/Zurich` inside `BlockMask._mask_local()` to compute the boolean mask, then use the mask on the UTC-indexed Series. `compare_hfc._align_for_comparison` (existing line 73-91) already shows the safe pattern with `.groupby(level=0).mean()` for duplicate-defense.
**Warning signs:** `pd.DatetimeIndex.has_duplicates` returns True on the local-converted index. **Always check** in the scorecard preflight.

### Pitfall 4: `BMonthEnd` does not honor CH/VS holidays
**What goes wrong:** `BMonthEnd(0)` returns last Mon-Fri of the month, ignoring CH holidays. If 31 Oct 2024 = Thu but Toussaint is a Friday holiday in some cantons (NOT VS — Toussaint isn't VS-recognised by `holidays` lib), the "last business day" may not be a true trading day for FMV.
**Why it happens:** `pandas.tseries.offsets.BMonthEnd` uses only the 5-business-day weekmask, no calendar.
**How to avoid:** For the 24 monthly vintages, this is a low-stakes issue (the PFC model itself doesn't care if vintage falls on a CH holiday — forwards file is delivered daily including holidays via `eex_report_path`). **Accept the convention "last weekday of month" as good-enough**, document it in 10-VERIFICATION.md. If user objects → swap to `pandas.tseries.offsets.CustomBusinessMonthEnd(holidays=ch_vs_holidays_arr)`. Each option is ~3 lines of code.
**Warning signs:** Vintage falls on Saint-Joseph (Tuesday 19 March 2024, NOT month-end so OK), Fête-Dieu (Thursday 30 May 2024, NOT month-end so OK), Assomption (Thursday 15 Aug 2024, NOT month-end so OK). **Empirically, 2024-2025 last-weekday-of-month never coincides with a VS holiday.** Verified via `holidays.country_holidays('CH', subdiv='VS', years=[2024, 2025])`.
**Provenance:** [VERIFIED: holidays library docs + manual cross-check of 24 month-end dates]

### Pitfall 5: MZ regression with degenerate residuals
**What goes wrong:** If the bloc + horizon cell has < 30 obs, OLS standard errors are unreliable and the F-test p-value may be misleading.
**Why it happens:** `block_summer_solar_bowl` × `horizon Y+2` × `1 vintage` produces ~3 hours/day × 4 months × 1 yr / 5 horizons ≈ small-sample regime.
**How to avoid:** Pool across the 24 vintages BEFORE computing MZ per (bloc × horizon). For each (bloc × horizon × config), concatenate all 24 vintage outputs into one long Series of (timestamp, pred, realised) and run a single OLS. Sample size becomes 24 × bloc_hours_per_vintage = order 1000s of obs. PROBLEM SOLVED.
**Warning signs:** `n_obs < 30` in the MZ result dict → flag the cell as "low-power MZ — interpret p-value with caution" in the scorecard table.

### Pitfall 6: 96-build seed determinism breaks across configs
**What goes wrong:** Config 1 (bowl OFF) and Config 4 (bowl ON) build differently. Even with `seed=42` for `Uncertainty`, the upstream `ShapeHourly` random state (currently none, deterministic by `_split_level_anomaly`) could pick up entropy from elsewhere.
**Why it happens:** Numerical ops on different code paths produce subtly different floats. Phase 5bis-A baseline contract `atol=1e-12` is the tolerance.
**How to avoid:** Apply the SAME tolerance contract (`assert_frame_equal(check_exact=False, atol=1e-12, rtol=0)`) for the scorecard re-run reproducibility test. Run the 96-grid TWICE on the same Mac Mini, save KPIs DataFrame, compare via `assert_frame_equal`. CONTEXT D-A6-3 locks this.
**Warning signs:** Tolerance violations on a re-run → either a new source of non-determinism was introduced (e.g. `numpy.random.default_rng()` without seed), or pandas/pyarrow patch-version drift. The 5bis-A REVIEWS addendum documents the fallback to `atol=1e-10` if CI versioning drift is observed.

### Pitfall 7: Compute budget blowout if Uncertainty enabled for all configs
**What goes wrong:** CONTEXT D-A6-1 says 4 configs × 24 vintages × ~25s = ~40min/config = ~4h. But `Uncertainty.fit(n_boot=500)` dominates wall-time, contributing ~60-90s/build extra.
**Why it happens:** Bootstrap loop O(n_boot × hourly_cells × percentile_compute).
**How to avoid:** **Pillar 3 only needs IC on Config 4 (production target)** — the SC#1 gate is on Config 4 too. Run `with_uncertainty=True` ONLY for the 24 builds of Config 4 (~ 36-50 min). Configs 1/2/3 run `with_uncertainty=False` (~ 10-15 min each = 30-45 min total). **Total ≈ 1h-1.5h Mac Mini, not 4h.** This is a major schedule optimization the planner should adopt.
**Warning signs:** None — pure planning decision.

    max_dev = 0.0

        if mask.sum() == 0:
            continue
        observed_mean = float(pfc[mask].mean())
        dev = abs(observed_mean - fwd_price)
        details[key] = {"observed": observed_mean, "forward": fwd_price, "dev": dev}
        max_dev = max(max_dev, dev)
    return TestResult(passed=max_dev < tol, observed=max_dev, threshold=tol, details=details)

def test_holiday_weekend(
    pfc: pd.Series, country: str = "CH", subdiv: str = "VS",
    range_: tuple[float, float] = (0.65, 0.95),
) -> TestResult:
    """Pillar 1.2 Hildmann: mean(PFC | weekend ∪ holidays) / mean(PFC | weekday) ∈ range."""
    idx_local = pfc.index.tz_convert("Europe/Zurich")
    years = sorted({d.year for d in idx_local})
    hols = holidays.country_holidays(country, subdiv=subdiv, years=years)
    is_weekend_or_hol = (idx_local.weekday >= 5) | np.array([d.date() in hols for d in idx_local])
    mean_off = float(pfc[is_weekend_or_hol].mean())
    mean_on = float(pfc[~is_weekend_or_hol].mean())
    if abs(mean_on) < 0.5:
        # Mean weekday near zero — ratio undefined; return passed=False
        return TestResult(passed=False, observed=float("nan"), threshold=range_,
                          details={"mean_off": mean_off, "mean_on": mean_on, "degenerate": True})
    ratio = mean_off / mean_on
    passed = range_[0] <= ratio <= range_[1]
    return TestResult(passed=passed, observed=ratio, threshold=range_,
                      details={"mean_off": mean_off, "mean_on": mean_on})

def test_seasonal_profile(
    pfc: pd.Series, epex_hist: pd.Series,
    period_pfc_years: tuple[int, int] = (2024, 2025),
    period_hist_years: tuple[int, int] = (2019, 2023),
    min_corr: float = 0.85,
) -> TestResult:
    """Pillar 1.3 Hildmann: pearson(monthly_PFC_signature, monthly_EPEX_hist_signature) > min."""
    pfc_2024_2025 = pfc[(pfc.index.year >= period_pfc_years[0]) & (pfc.index.year <= period_pfc_years[1])]
    hist_2019_2023 = epex_hist[(epex_hist.index.year >= period_hist_years[0]) & (epex_hist.index.year <= period_hist_years[1])]
    sig_pfc = pfc_2024_2025.groupby(pfc_2024_2025.index.month).mean()
    sig_hist = hist_2019_2023.groupby(hist_2019_2023.index.month).mean()
    common = sig_pfc.index.intersection(sig_hist.index)
    r, p_val = pearsonr(sig_pfc.loc[common], sig_hist.loc[common])
    return TestResult(passed=r > min_corr, observed=float(r), threshold=min_corr,
                      details={"pearson_r": float(r), "pearson_pvalue": float(p_val), "n_months": len(common)})

def test_continuity(pfc: pd.Series, max_jump: float = 2.0) -> TestResult:
    """Pillar 1.4 Hildmann: max |PFC[end of month M] - PFC[start of M+1]| < max_jump €/MWh."""
    idx_local = pfc.index.tz_convert("Europe/Zurich")
    # Last 15-min of each month vs first 15-min of next month
    month_period = idx_local.to_period("M")
    df = pd.DataFrame({"price": pfc.values, "month": month_period}, index=pfc.index)
    last_of_month = df.groupby("month").tail(1).set_index("month")["price"]
    first_of_month = df.groupby("month").head(1).set_index("month")["price"]
    aligned = pd.concat([last_of_month.shift(-0), first_of_month.shift(-1)], axis=1, join="inner")
    aligned.columns = ["last", "first_next"]
    aligned = aligned.dropna()
    jumps = (aligned["first_next"] - aligned["last"]).abs()
    max_jump_obs = float(jumps.max()) if len(jumps) > 0 else 0.0
    return TestResult(passed=max_jump_obs < max_jump, observed=max_jump_obs, threshold=max_jump,
                      details={"n_boundaries": int(len(jumps)), "all_jumps": jumps.to_dict()})
```

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| Hand-rolled DM test in MATLAB | R `forecast::dm.test()` with HLN correction + Bartlett HAC | ~2003 (forecast pkg release) | Python equivalent is maison ~30 lignes via `statsmodels.tsa.stattools.acovf` + `scipy.stats.t` |

| Comparison vs vendor benchmark (single point of failure) | Replication of SOTA literature quality criteria | Hildmann 2013 + KYOS/Volue convergence | Phase 10 design — SC#1 unique gate |
